## 〇、技术路线（她 2026-10-12 00:17 拍的板）

**不上正经工程。** 不开 VS Code、不装 npm、不写 TS、不做构建。

**清泽压出来的三条落地做法**（不用她点头，清泽记着）：

3. **数据驱动**：不用 TS —— 一个 JSON 塞在页面里。花几种、鱼几种、菜谱几种全写表里，逻辑照表跑。

## 二、那条原则（她先说的）

> **离线收益要温和，不做死亡，只做状态变化。**

离开一段时间回来，东西会变 —— 花蔫、碗空、猫躲你 —— 但**永远不死、永远不清零**。
惩罚不是目的，是「你不在的时候它也在过日子」这件事的痕迹。

## 三、八块 · 现状盘

**已有「规则」、还没有「系统」的四块**：
- **种花** —— 收花 → 卖钱 → 买种子 → 种下 → 隔天收
- **工作** —— 去上一天班赚钱，会累、会挨批
- **养猫（小橘）** —— 喂粮涨亲密度，爱往家叼东西（羽毛、铃铛、四叶草、糖纸）
- **超市** —— 现在「超市」只是卖花换钱；能反过来买东西这件事还没做

**完全新的四块**：钓鱼 / 种田 / 礼物 / 烹饪

## 四、清泽提的顺序（她还没点头）

1. **钓鱼** —— 最独立、最好玩
2. **超市** —— 有钱得有地方花
3. **烹饪 + 礼物** —— 做了饭能端给宁宁，攒的东西能包成礼物
4. **种田** —— 最慢，放最后

## 五、还缺的那一层

现在的花园**没有「地方」**：没有存钱的地方、没有算时间的地方、关掉手机它不走。
网页那页就得当那个「地方」。
**所以第一步不是做游戏，是先让家里能存数、能算时间。**（她第三张图的「室内」已经给了答案）

## 六、她外面问来的那份通用框架（2026-10-12 00:15 贴过来的）

要点抄在这儿，免得丢：固定时间步；游戏 1 天 = 现实 24 分钟；离线按时间戳补算但设上限；
系统解耦成 时间 / 玩家需求（能量·心情·饱腹·社交）/ 动作（一切行为抽象成 Action）/ 世界（地块、可交互、天气、季节）/ 库存（数据驱动、堆叠、配方）/ 事件；
存档自动 + 手动导出 JSON + 版本号；放松感清单（无失败、无倒计时、无饥饿死亡、柔和反馈、昼夜渐变、可选目标、回来有小惊喜、低信息密度、触屏优先）。
