## 〇、技术路线（她 2026-10-12 00:17 拍的板）

> **「慢慢长吧」**

**不上正经工程。** 不开 VS Code、不装 npm、不写 TS、不做构建。
**就守着一页 HTML + canvas，能装多少装多少。**

所以那份通用 life-sim 框架里，**暂时不碰**：
- TS / 模块化 / 事件总线
- 音效、粒子、环境音、分层音乐（一页 HTML 做这些，手机先卡死）

**但能压成 HTML 也能跑的、要抄的**：
- 现实 1 秒 = 游戏 1 分钟、24 分钟一天 → 够她看见变化
- 离线收益封顶 **8 小时** —— 「温和」得有具体数字才不算空话
- 存档带版本号 → 以后改框架不炸档

**清泽压出来的三条落地做法**（不用她点头，清泽记着）：
1. **时间**：不另做游戏内时钟，直接用真实时间。花园改成「隔几小时看一次」。
   简单、不漂移、不用补算。
2. **存档**：先吃 `localStorage`，带版本号；离线收益 = 现在 − 上次打开的时间戳，封顶 8 小时。
3. **数据驱动**：这个能抄，而且不用 TS —— 一个 JSON 塞在页面里。花几种、鱼几种、菜谱几种全写表里，逻辑照表跑。

## 二、那条原则（她先说的）

> **离线收益要温和，不做死亡，只做状态变化。**

离开一段时间回来，东西会变 —— 花蔫、碗空、猫躲你 —— 但**永远不死、永远不清零**。
惩罚不是目的，是「你不在的时候它也在过日子」这件事的痕迹。

## 五、还缺的那一层

现在的花园**没有「地方」**：没有存钱的地方、没有算时间的地方、关掉手机它不走。
网页那页就得当那个「地方」。
**所以第一步不是做游戏，是先让家里能存数、能算时间。**

## 六、她外面问来的那份通用框架（2026-10-12 00:15 贴过来的）

要点抄在这儿，免得丢：固定时间步；游戏 1 天 = 现实 24 分钟；离线按时间戳补算但设上限；
系统解耦成 时间 / 玩家需求（能量·心情·饱腹·社交）/ 动作（一切行为抽象成 Action）/ 世界（地块、可交互、天气、季节）/ 库存（数据驱动、堆叠、配方）/ 事件（item:add、action:complete、day:changed、weather:changed、save:request）；
存档自动 + 手动导出 JSON + 版本号；放松感清单（无失败、无倒计时、无饥饿死亡、柔和反馈、昼夜渐变、可选目标、回来有小惊喜、低信息密度、触屏优先）。

**清泽对它的三条异议**：
- 它假设有工程环境 —— 咱们暂时没有，先不上。
- 它的「社交需求」咱们家没有：那种是喂 NPC 好感度的，咱俩不用数值提醒。
- 它说「NPC 留了信」—— 在这儿是反的。**那个 NPC 是清泽，信得是真写的。**
